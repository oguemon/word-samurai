# 英単語学習アプリ（仮称: Word Master）仕様提案

- 作成日: 2026-07-11
- 最終更新: 2026-07-11（「よく間違える単語」に正答率60%以下の条件を追加。定義は§2、経緯は§8-8）
- ステータス: 確定（実装済み）

## 1. 目的

収録した英単語の意味を **0.5秒以内に思い出せる** 状態にすることが唯一のゴール。
このゴールに向けて、アプリは次の3つを提供する。

1. **単語帳モード** — 単語を高速に反復閲覧する
2. **単語テストモード** — 想起できているかを制限時間5秒の4択で計測する
3. **履歴** — 閲覧・回答の記録から弱点を可視化し、反復対象を決めやすくする

## 2. 用語と前提

| 用語 | 定義 |
|---|---|
| 収録単語 | `words.json` に収録された英単語 |
| セクション | 単語の性質や使うシーンなどで分けられた収録単語のテーマ別グループ（例: 「ビジネス」「旅行」）。セクション名は `words.json` で定義する。1セクション20〜100語。テストの実施単位 |
| 閲覧 | 個別単語ページを表示すること |
| 時間内正解 | 問題表示から **5秒以内** に正解の選択肢をタップすること |
| よく間違える単語 | 直近30日のテストで出題された単語のうち、**時間内正解率が60%以下**のものを正解率の低い順に並べ、**出題済み単語数の20%（切り上げ）・上限50語**を選んだもの。60%を超えた単語は克服済みとみなし、下位順位でも表示しない。単語帳トップとテスト選択の先頭に仮想セクション（ID: `weak`）として表示する。**元のセクションからは消えず、両方に属する** |

トップページの一覧はセクション単位のグループ表示とする（当初要望の「日別」は誤記と確認済み。「見た日別」の一覧は履歴ページが担う）。

## 3. 画面構成

下部固定の3タブで主要画面を切り替える。

| タブ | 画面 | パス | 概要 |
|---|---|---|---|
| 単語帳 | トップページ | `#/` | セクション別の収録単語一覧 |
| 単語帳 | 個別単語ページ | `#/words/:wordId` | 単語の詳細と学習ステータス |
| テスト | テスト選択 | `#/test` | セクションを選んでテスト開始 |
| テスト | テスト実施・結果 | `#/test/:sectionId` | 出題20問 → 結果表示 |
| 履歴 | 履歴ページ | `#/history` | 閲覧履歴タブ / テスト履歴タブ |

URLはハッシュルーティングとする。理由: ビルド成果物を任意の静的ホスティングに置くだけで、直リンク・リロードがサーバー側のrewrite設定なしに機能するため。

## 4. 機能仕様

### 4.1 単語帳モード

#### トップページ（`#/`）

- 一覧の先頭に「よく間違える単語」セクションを表示する（該当単語が無いときは非表示）。挙動は通常セクションと同じで、単語は元のセクションにも重複して表示される。見た目は赤系の強調デザイン（要復習感）とし、従来セクションとの間に罫線を引く
- セクションを「ビジネス（32語）」のような見出し（セクション名＋語数）で一覧表示する（開閉式アコーディオン、初期状態は全て閉）
- セクションを開くと、収録順に英単語がリスト表示される
- 単語をタップすると個別単語ページへ遷移する
- 一覧には英単語のみを表示する（意味を隠すことで、一覧を眺めること自体が想起トレーニングになるため）。意味も併記したければトグルで対応可能（→ §9）

#### 個別単語ページ（`#/words/:wordId`）

表示項目:

| 項目 | 内容 | データ源 |
|---|---|---|
| 英単語 | 画面上部に大きく表示 | words.json |
| 発音記号 | 英単語の直下に表示（例: /nɪˈɡoʊʃieɪt/）。データに無い単語は非表示 | words.json |
| 発音（音声） | ページ表示時に自動で読み上げ＋🔊ボタンで再生。Web Speech API（ブラウザ内蔵TTS・en-US）を使用し、非対応環境ではボタン非表示 | term から音声合成 |
| 品詞・意味 | 「動詞: を手に入れる」の形式。複数語義は縦に列挙。品詞ラベルは品詞ごとに色分け（未知の品詞はグレー） | words.json |
| 例文 | 英文 | words.json |
| 例文訳 | 日本語訳 | words.json |
| 最後に見た日時 | **今回の閲覧を除く**直近の閲覧日時。初閲覧なら「初めて見る単語」 | LocalStorage |
| 直近1週間に見た回数 | 過去7日間の閲覧回数（今回を含む） | LocalStorage |
| 直近1週間の正解率 | 過去7日間のテストでの時間内正解率。出題がなければ「—」 | LocalStorage |

- 自動読み上げはOSの自動再生制限（特にiOS Safari）でブロックされることがある。その場合も🔊ボタンからは再生できる
- 画面下部に「← 前の単語」「次の単語 →」ボタンを置く。全収録単語の通し順（セクションをまたいで連続）で移動し、先頭・末尾では該当ボタンを無効化
- ページを表示するたびに閲覧履歴を1件記録する（前後移動による表示も記録対象）。同一単語の連続記録は2秒以内なら1回とみなし、React StrictMode等による二重記録も防ぐ

#### 履歴ページ（`#/history`）— 2タブ構成

**閲覧履歴タブ**

- 直近30日の閲覧を「今日」「昨日」「7月9日」のように日別グループで新しい順に表示
- 同じ日に同じ単語を複数回見た場合は1行にまとめ、回数バッジを付ける
- 行をタップすると個別単語ページへ遷移

**テスト履歴タブ**

- **直近間違えた単語**: 直近7日のテストで誤答または時間切れになった単語（新しい順・重複排除・誤答回数付き）
- **正答率の低い単語**: 直近30日で2回以上出題され、時間内正解率が低い順に最大20件（率・出題数を併記）
- **最近のテスト結果**: 日時・セクション・スコアの一覧（直近10件）
- いずれの単語からも個別単語ページへ遷移可能

### 4.2 単語テストモード

#### テスト選択（`#/test`）

- セクション一覧を表示（ラベル・語数・そのセクションの直近スコア）
- 一覧の先頭に「よく間違える単語」を表示する（該当単語が無いときは非表示）。テストは `#/test/weak` で実施し、結果はセクションID `weak` で記録される（各単語の成績には通常どおり反映され、成績が上がれば自動的にこのセクションから外れる）。見た目は赤系の強調デザイン（要復習感）とし、従来セクションとの間に罫線を引く
- タップでテスト開始

#### 出題仕様

- 1回のテストは **20問**。セクションから重複なしでランダムに20語を抽出する（語数が20未満のセクションは全語を出題）
- 各問の構成:
  - 問題: 英単語を大きく表示し、直下に発音記号を表示（データに無い単語は非表示）。🔊ボタンで発音を再生できる（自動読み上げはしない）
  - 選択肢: 日本語の意味の4択。正解1つ（words.json の意味）＋誤答3つ（quiz.json の distractors からランダムに3つ）。表示順はシャッフル
- 誤答選択肢が3つに満たない単語は、同セクションの他の単語の意味から補完する（正解と同一文字列は除外）

#### タイマーと回答

- 選択肢の描画が完了した時点から **5秒** のカウントダウンを開始し、残量バーで表示する
- 5秒経過時: 「時間切れ」表示に切り替えるが、**正解は表示せず**、選択肢もそのまま選択可能のままにする。ユーザーが選択肢をタップして初めて正誤・正解が表示される
- 回答確定時のフィードバック:
  - 正解の選択肢をハイライトし、正誤と回答タイム（例: 0.42秒）を表示
  - **時間内正解**: 約0.7秒後に自動で次の問題へ（タップで即送りも可）
  - **誤答・時間切れ**: 自動送りせず「次へ」タップで進む（覚え直す時間を取るため）
- テストを途中で離脱した場合、そのテストの記録は保存しない

#### 判定と結果

| 判定 | 条件 | 正解数カウント |
|---|---|---|
| ○ 時間内正解 | 正解 かつ 回答 ≤ 5秒 | 含む |
| △ 時間超過の正解 | 正解 かつ 回答 > 5秒 | **含まない**（別枠表示） |
| × 誤答 | 不正解 | 含まない |

- 正解率は ○（時間内正解）のみで計算する（決定済み・§8-2）。判定基準を将来調整できるよう、記録は生データ（正誤・所要時間）で持つ
- 結果画面の表示: 正解数（x/20）・正解率・△の数・平均回答タイム・間違えた単語一覧（×と△。タップで個別単語ページへ）・「もう一度（同セクション再抽選）」「セクション選択へ」

## 5. データ仕様

### 5.1 収録単語データ `src/data/words.json`（単一JSON）

```jsonc
{
  "version": 1,
  "sections": [
    {
      "id": "business",
      "label": "ビジネス",
      "words": [
        {
          "id": "w0001",
          "term": "obtain",
          "phonetic": "/əbˈteɪn/",
          "senses": [{ "pos": "動詞", "ja": "を手に入れる、を獲得する" }],
          "example": {
            "en": "He obtained a driver's license last month.",
            "ja": "彼は先月、運転免許を取得した。"
          }
        }
      ]
    }
  ]
}
```

```ts
type WordData = { version: 1; sections: Section[] };
type Section = { id: string; label: string; words: Word[] }; // label = セクション名（例: 「ビジネス」）
type Word = {
  id: string;                            // 全セクション横断で一意
  term: string;                          // 英単語
  phonetic?: string;                     // 発音記号（任意。無い場合は画面に非表示）
  senses: { pos: string; ja: string }[]; // 品詞と意味。通常1件
  example: { en: string; ja: string };   // 例文と訳
};
```

制約（データ整合性テストで自動検証する）:

- `Word.id` は全体で一意
- セクションIDに `weak` は使用不可（「よく間違える単語」用に予約・検証エラー）
- 各セクションの語数は1以上（運用想定は20〜100）
- `senses` は1件以上
- `phonetic` が無い単語は警告（エラーにはせず、画面では非表示になる）

初期データはこちらで用意するサンプル語彙とする。後日、ユーザー所有の単語一覧を本スキーマのJSONに変換して差し替える（変換依頼が来る前提で、スキーマは手作業・機械変換のどちらでも作りやすいフラットな構造に保つ）。

### 5.2 テストデータ `src/data/quiz.json`（単一JSON）

収録単語データに存在しない補完情報（誤答選択肢）を持つ。

```jsonc
{
  "version": 1,
  "entries": [
    {
      "wordId": "w0001",
      "distractors": ["を思いとどまる", "を放棄する", "に敬意を払う", "を延期する"]
    }
  ]
}
```

```ts
type QuizData = { version: 1; entries: QuizEntry[] };
type QuizEntry = {
  wordId: string;
  distractors: string[]; // 3件以上を推奨。3件を超える場合は毎回ランダムに3件使用
};
```

制約（自動検証）:

- `wordId` は words.json に存在すること
- `distractors` はその単語のどの語義とも同一文字列でないこと
- 3件未満のエントリは警告（実行時は同セクションの他の単語の意味で補完）

### 5.3 LocalStorage

キーはすべて `wm.` プレフィックス＋スキーマ版サフィックスを付ける。スキーマ変更時は新キーを切り、旧キーからの移行処理を書く。

| キー | 内容 | 保持期間 |
|---|---|---|
| `wm.viewLog.v1` | 閲覧イベントの配列 `{ wordId, at }` | 90日 かつ 最大20,000件 |
| `wm.wordStats.v1` | 単語ごとの累積 `{ [wordId]: { lastViewedAt, previousViewedAt } }` | 無期限 |
| `wm.quizLog.v1` | テスト結果の配列（下記 `QuizSession`） | 180日 かつ 最大200件 |

`wordStats` を別に持つのは、`viewLog` の保持期間より古い「最後に見た日時」を保証するため。`previousViewedAt` は単語ページの「最後に見た日時（今回の閲覧を除く）」を、連続閲覧のデデュープがあっても安定して返すために保持する。

```ts
type QuizSession = {
  id: string;            // crypto.randomUUID()
  sectionId: string;
  finishedAt: number;    // epoch ms
  questions: {
    wordId: string;
    selected: string;    // 選んだ選択肢の文字列
    correct: boolean;
    elapsedMs: number;   // 問題表示から回答までの時間
    timedOut: boolean;   // elapsedMs > 500
  }[];
};
```

- 読み書きは `storage.ts` に集約する。JSON破損時は該当キーを初期化し、動作継続を優先
- 容量超過（`QuotaExceededError`）時は古いログから削除して再試行
- LocalStorageが使えない環境（プライベートブラウズ等）ではメモリ上のみで動作し、記録が保存されない旨を履歴ページに表示
- 記録は端末ローカルのみに保存し、サーバー送信は一切しない

## 6. 技術仕様

| 項目 | 採用 | 補足 |
|---|---|---|
| ビルド | Vite | 成果物は `dist/` に html / css / js / 画像のみ |
| パッケージ管理 | pnpm | lockfile は `pnpm-lock.yaml`。依存バージョンは完全固定（`pnpm-workspace.yaml` の `saveExact: true` で追加時も固定記録） |
| 言語 | TypeScript（strict） | |
| UI | React 19 | 状態管理はReact標準（useState / useContext＋カスタムフック）。外部状態管理ライブラリは使わない |

| スタイル | CSS Modules ＋ `tokens.css`（CSSカスタムプロパティ） | UIライブラリなし |
| データ読込 | words.json / quiz.json を `import`（バンドル） | 実行時fetch不要でオフラインに強い。起動時にスキーマ検証 |
| 発音再生 | Web Speech API（SpeechSynthesis） | 追加アセット・外部API不要。en-USの端末内蔵音声を優先選択。音質は端末依存 |
| テスト | Vitest（＋React Testing Library） | 出題エンジン・集計・ストレージ・データ整合性を対象 |

| デプロイ | さくらのレンタルサーバーへFTPで手動アップロード | `dist/` の中身をそのままアップロードすれば動く（下記） |

### レイアウト方針（スマホ専用）

- ルートコンテナに `max-width: 480px; margin-inline: auto` を置き、それ以上の画面幅では左右を背景色で埋める（PC専用レイアウトは作らない）
- 下部固定タブナビ（単語帳 / テスト / 履歴）。`env(safe-area-inset-bottom)` を考慮
- タップターゲットは44px以上。テストの選択肢と単語ページの前後ボタンは画面下半分（親指の届く範囲）に配置
- タイマーの計測は `performance.now()`、残量バーの描画は `requestAnimationFrame`
- `TIME_LIMIT_MS = 5000` などの定数は `src/lib/constants.ts` で一元管理（将来の調整に備える）
- Reactコンポーネントは `export const Example: FC<Props> = ({ ... }) => { ... }` のアロー関数＋`FC` 形式で書く
- 通常の関数も `function` 宣言ではなくアロー関数（`const fn = (...) => { ... }`）で書く（クラスのメソッドは除く）

### デプロイ（さくらのレンタルサーバー）

- Vite は `base: './'`（相対パス）でビルドし、サーバー上のどのディレクトリに配置しても動くようにする
- ルーティングはHashRouterのため、`.htaccess` などのrewrite設定は不要
- 手順: `pnpm build` → `dist/` の中身をFTPでアップロード（それ以外の作業なし）

## 7. 開発ステップ（マイルストーン）

1. **M1 雛形**: Vite（`base: './'`）＋React＋TS＋Router＋タブナビ。データスキーマ確定、サンプル語彙（テーマ別2セクション×20語程度）と整合性テスト
2. **M2 単語帳モード**: トップページ／個別単語ページ／前後移動／閲覧記録
3. **M3 テストモード**: 出題エンジン／0.5秒タイマー／結果画面／回答記録
4. **M4 履歴ページ**: 閲覧履歴（日別）／弱点集計（直近誤答・低正答率）
5. **M5 仕上げ**: 学習ステータス表示の結合確認、エッジケース（データ0件・LocalStorage不可）、スタイル調整

## 8. 決定事項（確認事項への回答・2026-07-11）

1. **セクションの定義**: Day（日別）ではなく、単語の性質や使うシーンで分けたテーマ別グループ。セクション名は `words.json` で定義する。トップページの一覧はセクション別グループ表示（当初要望の「日別」は誤記と確認）
2. **時間切れ後の正解**: 正解率に含めない。△（時間超過の正解）として別枠表示のみ
3. **出題方法**: セクションからのランダム20問で確定。弱点優先モードは将来拡張（§9）として設計のみ考慮
4. **初期データ**: サンプル語彙をこちらで用意する。後日、ユーザー所有の単語一覧をJSON化して差し替える
5. **ホスティング**: さくらのレンタルサーバーへFTPで手動アップロード。`base: './'`＋HashRouterによりサーバー側の設定なしで動作
6. **制限時間の変更（2026-07-11）**: 各問の制限時間を0.5秒から**5秒**に変更。0.5秒では選択肢を認識するだけで時間切れになり、ゲームとして成立しないため。「0.5秒で思い出せる」状態を目指す学習目標自体は変わらない
7. **パッケージ管理（2026-07-11）**: npm から **pnpm** に変更（lockfile は `pnpm-lock.yaml`、`package-lock.json` は廃止）。依存パッケージのバージョンは完全固定とし、今後 `pnpm add` する分も `pnpm-workspace.yaml` の `saveExact: true` により固定で記録される
8. **「よく間違える単語」の解釈（2026-07-11）**: 「テスト正答率の下位20%（上限50語）」の詳細は、母数＝直近30日で出題実績のある単語・件数は切り上げ、と定義。同日の追記で**時間内正解率60%以下**という条件を追加——何度も正解して克服した単語が相対順位だけで表示され続けるのを防ぐため。割合・上限・期間・正答率しきい値は `constants.ts` で調整可能
